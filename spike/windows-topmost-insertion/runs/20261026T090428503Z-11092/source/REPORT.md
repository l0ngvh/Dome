## Local observation scope

Ordinary setup steps, immediate native-write observations, reference polls, held intervals, releases and settlement samples use local snapshots. Both `fixtures` and `fixture_rereads` retain handle, validity, process/thread identity, extended style and style-read error, decoded topmost flag, visibility, owner and immediate neighbors. The collector reads every fixture in full again after neighbor traversal, including fixtures already encountered on another fixture's path. Timestamps bound all native reads, with `finished_us` after the full rereads and any diagnostics. Settlement and reference-poll records retain sample indices.

Lightweight neighbor nodes retain handle, validity, process/thread identity and both links. The collector reads each fixture and its immediate neighbors, then follows at most 32 downward links per fixture, stopping at another fixture or the chain end. Nodes are deduplicated within one snapshot, not cached across samples. Unrelated windows on these paths need no style or class reads.

Validation requires independent, visible, unowned fixtures with valid style decoding. Rust and Python independently require both full fixture arrays to match in every field. Independent fixture and neighbor reads must also agree on identity and links. Every fixture's nonzero immediate neighbor must be present. Recorded links must be reciprocal wherever both endpoints exist, and cycles are rejected. Nonadjacent relative order needs a complete reciprocal path between the requested endpoints. A truncated path leaves the relation unknown. Fixture list order is never order evidence, and local analysis reports no global fixture order or global topmost census.

## Native ordering and timing

A, B and normalA own unowned windows on separate processes' main threads. X is an unowned nonactivating tool popup on the coordinator thread. Each C race trial creates a separate process. Calls use `SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE`, adding `SWP_ASYNCWINDOWPOS` only for deliberate queued writes. Synchronous fixture calls run on their owning thread.

Every API call retains arguments, caller identity, result, failure details and start/return timestamps. Local and asynchronous calls take their immediate native observation before JSON serialization. A fixture process takes an immediate target read before serializing its response. The coordinator takes its scoped observation when that response arrives, before serializing the reply into the raw stream. Release observations use the same deferred-recording path. Required interprocess transport remains part of observation delay.

A treatment observation can precede its `treatment_call` record in the file. Analysis brackets calls using native timestamps, not emission order. Each record is serialized into an ordinary temporary byte buffer and written once. There is no asynchronous writer or compact-export mode. The successful reference poll itself becomes `reference_transition_observed`, without another snapshot.

Pump holds keep the owner thread responsive to release commands without dispatching window messages. The requested 100 ms held interval and 25 ms settlement sleeps remain. Each completed case has 21 settlement samples, and repeat insertion has another 21 before its second write. Five repetitions of the full matrix produce 2,310 settlement samples. These are requests and counts, not a cadence guarantee. Analysis reports read spans, between-read gaps, settlement span, hold span and the held-after-write gap.

The final five samples must agree on measured band and neighbors. An unproven relative order remains unknown even when those facts settle. API success, elapsed time and release acknowledgements alone do not establish a queued endpoint.

## Streaming and compatibility

The launcher computes summary counters one line at a time. The Python parser analyzes and discards each completed trial before reading the next, retaining session/creation identities and compact results. Malformed lines, partial trials, duplicate or incomplete matrices and cleanup failures still prevent an all-passing result.

Schema 2 keeps its original callback-order interpretation. The preserved failed run produces exactly the report from its embedded analyzer. Schema 3 requires raw enumeration and checks its serialized canonical order against independent reconstruction. Schema 4 requires an explicit scope and rejects global records outside global-premise stages. Use each run's embedded analyzer to reproduce its historical verdict. Replay repairs no legacy timing bound.
